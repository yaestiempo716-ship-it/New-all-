Qué esCLAUDE.md 是什么

Es un archivo de memoria persistente que Claude Code carga automáticamente en el contexto al inicio de cada sesión, antes de que escribas nada. 它是一个持久化记忆文件。Claude Code 会在每次会话开始时自动把它读入上下文——在你输入任何内容之前。

No es documentación para humanos: es instrucción para el agente. Todo lo que pongas ahí se paga en tokens en cada conversación. 它不是给人看的文档，而是给智能体的指令。你写进去的每一行，都会在每一次对话里消耗 token。

Esa doble naturaleza explica casi todas las decisiones de este documento: es potente porque siempre está presente, y es caro por exactamente la misma razón. 这种双重性质几乎解释了本文所有的取舍：它之所以强大，是因为它始终在场；而它之所以昂贵，恰恰也是同一个原因。

Jerarquía de carga加载层级

Claude Code busca y concatena varios niveles. La sangría de abajo es literal: cuanto más a la derecha, más específico y más peso tiene sobre lo anterior. Claude Code 会查找并拼接多个层级。下面的缩进就是字面意义上的层级——越靠右越具体，对上层的覆盖力也越强。

General 通用Específico 具体
/etc/claude-code/CLAUDE.md
Toda la máquina · 全机器
Políticas corporativas, desplegadas por el administrador. 企业级策略，由管理员统一下发。
~/.claude/CLAUDE.md
Todos tus proyectos · 你的所有项目
Preferencias personales: idioma de las respuestas, estilo, herramientas que prefieres. 个人偏好：回复语言、风格、你惯用的工具。
<repo>/CLAUDE.md
El proyecto, compartido en git · 项目级，随 git 共享
El importante. Comandos, arquitectura y convenciones del equipo. Se commitea. 最关键的一个。团队的命令、架构与约定。要提交进版本库。
<repo>/CLAUDE.local.md
El proyecto, solo tú · 项目级，仅本人
Rutas locales y ajustes de tu máquina; va al .gitignore. En desuso: hoy es preferible el archivo de ~/.claude/. 本机路径和个人设置，需加入 .gitignore。已不推荐：现在更建议放在 ~/.claude/ 里。
<repo>/apps/web/CLAUDE.md
Un subdirectorio · 子目录级
Reglas de un paquete concreto dentro de un monorepo. monorepo 中某个具体子包的规则。

Dos detalles que cambian cómo lo organizas两个会影响你组织方式的细节

  • Recursión hacia arriba. Si trabajas en /repo/apps/web/, se carga /repo/CLAUDE.md y /repo/apps/web/CLAUDE.md. No se sustituyen: se suman. 向上递归。如果你在 /repo/apps/web/ 下工作，/repo/CLAUDE.md 和 /repo/apps/web/CLAUDE.md 都会被加载。它们是叠加关系，不是替换关系。
  • Carga bajo demanda. Los de subdirectorio no entran al arrancar, sino cuando tocas archivos de esa carpeta. Por eso un monorepo puede tener muchos sin inflar cada sesión. 按需加载。子目录的文件不会在启动时载入，而是在你实际操作该目录下的文件时才载入。所以 monorepo 可以放很多个，而不会让每次会话都变臃肿。

Imports用 @ 引用其他文件

Con @ruta/archivo.md incluyes otro archivo. Sirve para mantener el CLAUDE.md corto y dejar el detalle en documentos que solo se leen cuando hacen falta. 用 @路径/文件.md 可以引入另一个文件。这样能让 CLAUDE.md 保持简短，把细节留在真正需要时才读的文档里。 

# Proyecto X

Comandos y convenciones: ver abajo.
Arquitectura detallada en @docs/architecture.md
Guía de estilo del API en @docs/api-style.md

Cómo crearlo y editarlo如何创建与编辑

/init

Genera uno analizando el codebase. Buen punto de partida — pero luego hay que podarlo. 通过分析代码库自动生成一份。是不错的起点——但之后必须精简。

# al inicio del mensaje

Añade esa línea a la memoria sin salir de la sesión. Ej: # usa pnpm, nunca npm. 无需离开当前会话即可把这一行写入记忆。例如：# 用 pnpm，不要用 npm。

/memory

Abre los archivos de memoria en tu editor para revisarlos y limpiarlos a fondo. 在编辑器中打开各层记忆文件，便于通读和彻底整理。

Por qué importa为何重要

Sin CLAUDE.md, Claude redescubre tu proyecto en cada sesión: lee el package.json, adivina el gestor de paquetes, prueba npm test cuando en realidad usas make test, y reinventa un patrón que tú ya tenías resuelto. 没有 CLAUDE.md，Claude 会在每次会话里重新摸索你的项目：读 package.json、猜包管理器、执行 npm test——而你其实用的是 make test——并重新发明一个你早已解决过的模式。

El valor real no es «ahorrar explicaciones». Es eliminar la clase de errores que se repiten. 它真正的价值不是「少解释几句」，而是消除那一类反复出现的错误。

Regla de las tres veces: si has tenido que corregir lo mismo tres veces, esa corrección ya no pertenece al chat — pertenece al CLAUDE.md. 「三次法则」：同一件事你纠正了三遍，那它就不该再留在对话里——它属于 CLAUDE.md。

Qué poner y qué no该写什么，不该写什么

El criterio, en una pregunta: ¿un desarrollador nuevo, competente pero sin contexto, se equivocaría sin esto? Si la respuesta es sí, va dentro. 判断标准就一句话：一个能力不差、但对项目毫无背景的新同事，如果不知道这条，会不会犯错？会，就写进去。

Sí / 该写

  • Comandos reales de build, test y lint — sobre todo los que no son el default. 真实的构建、测试、lint 命令——尤其是与默认约定不同的那些。
  • Convenciones que difieren del ecosistema (gestor de paquetes, estilo, patrones prohibidos). 与生态默认做法不同的约定（包管理器、代码风格、禁用模式）。
  • Límites de arquitectura: qué módulo no puede importar a cuál. 架构边界：哪个模块不能依赖哪个模块。
  • Trampas conocidas: cosas que parecen rotas y no lo están. 已知的坑：那些看起来像故障、其实正常的情况。

No / 不该写

  • Explicaciones de lo que el código ya dice. Claude sabe leer. 代码本身已经说明的内容。Claude 会读代码。
  • Documentación para humanos. Eso es el README.md: otro público, otro propósito. 面向人的文档。那是 README.md 的事：受众不同，目的也不同。
  • Consejos genéricos («escribe código limpio»). Ruido sin efecto. 泛泛的建议（「写干净的代码」）。只是噪音，毫无作用。
  • Secretos. Este archivo va a git y entra en el contexto del modelo. 密钥。这个文件会进版本库，也会进入模型上下文。
  • Contenido que caduca (roadmaps, estado del sprint): luego da instrucciones falsas. 会过期的内容（路线图、迭代状态）：过后就变成了错误指令。

Ejemplo de contenido que sí gana su sitio / 值得占位的内容示例

## Comandos
- Tests: `make test` (NO `npm test`, está roto)
- Un solo test: `pytest tests/x.py::test_y -x`
- Lint antes de commit: `./scripts/check.sh`

## Convenciones
- Gestor de paquetes: pnpm. Nunca npm ni yarn.
- No usar `any` en TypeScript; preferimos `unknown` + narrowing.
- Migraciones: nunca editar una existente, crear una nueva.

## Arquitectura
- `src/core/` no puede importar de `src/ui/` (dependencia unidireccional).
- La auth vive en `src/auth/`; todo pasa por `verifySession()`.

## Trampas conocidas
- El servidor de dev tarda ~40s en arrancar, no lo mates antes.
- Los tests de `integration/` necesitan Docker levantado.

Y un aviso sobre el tamaño: un CLAUDE.md de 800 líneas se diluye. Las instrucciones importantes acaban compitiendo con las triviales, y el modelo empieza a ignorarlas. 另外关于篇幅：一份 800 行的 CLAUDE.md 会被稀释。重要指令最终与琐碎内容争夺注意力，模型也就开始忽略它们了。

Cuándo usarlo y cuándo no何时该用，何时不必

Vale la pena / 值得写

  • Proyecto al que vas a volver. 你还会反复回来的项目。
  • El build o los tests tienen pasos no obvios. 构建或测试有不显而易见的步骤。
  • Hay convenciones distintas del default del ecosistema. 存在与生态默认不同的约定。
  • Trabajas en equipo y quieres código consistente para todos — por eso el del repo se commitea. 团队协作，希望所有人得到一致的产出——这正是仓库里那份要提交的原因。
  • Monorepo: uno raíz corto + uno por paquete con lo específico. monorepo：根目录放一份精简的，每个子包再放各自的。

No hace falta / 不必写

  • Script de un solo uso o exploración de una tarde. 一次性脚本，或一个下午的探索。
  • Proyecto convencional donde los defaults funcionan. 完全常规的项目，默认约定就能跑通。
  • Instrucción para esta tarea concreta: dila en el prompt, no en la memoria. 只针对当前这一个任务的要求：在对话里说就行，不必写进记忆。
  • Un repo que solo lees y no modificas. 只读、不改动的仓库。

Reglas prácticas实用规则

01

Corto y en imperativo. Bullets, no prosa. «Usa X», no «en este proyecto tendemos a preferir X porque…». 简短、用祈使句。写要点，不写散文。用「使用 X」，而不是「本项目中我们倾向于偏好 X，因为……」。

02

Empieza vacío y añade cuando algo falle, no anticipando fallos imaginarios. 从空文件开始，出问题时再补一条，不要预先设想那些还没发生的问题。

03

Marca solo lo crítico. IMPORTANTE: o NUNCA: en las dos o tres reglas que de verdad no pueden romperse. Si marcas todo como importante, nada lo es. 只标注真正关键的。用 重要： 或 绝不： 标注那两三条绝不能破的规则。全都标成重要，就等于没有重要。

04

Revísalo cuando el proyecto cambie. Una instrucción obsoleta hace daño activo: Claude la seguirá con confianza. 项目变了就回头修订。过时的指令是有害的：Claude 会毫不犹豫地照做。

05

Objetivo de tamaño: que quepa en una pantalla. Si crece, mueve el detalle a otros archivos y usa @import. 篇幅目标：一屏放得下。如果变长了，把细节移到别的文件，用 @ 引用。

Ejemplo mínimo real / 一份真实的最小示例

# api-service

## Comandos
- Dev: `docker compose up` (requiere .env, ver .env.example)
- Test: `pytest` — un test: `pytest path::name -x`
- Lint: `ruff check . && mypy .` — obligatorio antes de commit

## Reglas
- Python 3.12, gestor: uv. NUNCA pip install directo.
- IMPORTANTE: no editar `migrations/` existentes,
  crear nuevas con `alembic revision`.
- Endpoints nuevos -> anadir test en `tests/api/`.
- Errores: usar `AppError` de `src/errors.py`, no raise generico.

Eso, en unas quince líneas, evita más errores repetidos que trescientas líneas describiendo la arquitectura. 这短短十五行，比三百行的架构描述更能避免重复出错。
